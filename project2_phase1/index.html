What is LangChain?

Building blocks for LLM applications.

When we call an LLM API directly, we usually send a prompt and receive a text response. LangChain adds reusable building blocks around the model so we can create more organized and repeatable LLM workflows.

Some useful building blocks are prompt templates, LLM wrappers, chains, and output parsers. LangChain also makes it easier to work with different LLM providers without rewriting the whole application.

A simple LangChain chain

→

Output
prompt | llm | parser

The | operator is part of LCEL (LangChain Expression Language).

02

Prompt Templates & Output Parsers

Make prompts reusable and responses easier to use in code.

Prompt Template

A prompt template is a prompt with placeholders. Instead of writing the same prompt again, we can provide a different value for the variable. 

prompt = PromptTemplate.from_template(
    "Explain {topic} in simple English."
)

prompt.invoke({"topic": "LangChain"})

Output Parser

LLMs normally return free-form text. An output parser helps turn that response into a form our program can work with more reliably. 

{
  "topic": "LangChain",
  "summary": "A framework for LLM apps"
}

Common concepts include StrOutputParser, JsonOutputParser, structured output, and Pydantic models.

03

Memory & Tool Calling

Give an LLM useful context and access to external actions.

Memory

An LLM call is normally independent. If an application needs the bot to refer to earlier messages, it must keep the conversation history and provide the relevant history to later calls.

User message → Chat history → LLM

Tool Calling

Tool calling lets an LLM use functions instead of trying to answer everything from its own knowledge. A tool could be a calculator, search function, or database lookup.

Question → LLM → Tool → Result

The model can decide when a tool is needed and what information should be passed to it.

04

What is LangGraph?

Useful when an application needs decisions and changing paths.

Chain vs Agent

A chain follows a fixed sequence. The same steps happen in the same order.

A→B→C

An agent can look at the situation and decide what to do next. It may choose between paths, repeat a step, or skip a step.

A→Decision →
B C

Why LangGraph?

LangGraph represents these decision-making workflows as a graph. It gives us a way to define steps, connect them, make decisions, and carry shared data through the workflow.

NodeA step in the graph.
EdgeA connection between steps.
Conditional edgeA route chosen from a result or condition.
StateData that moves through and is updated by the graph.

Orchestrator Agents

A manager that decides which specialized agent should handle the work.

An orchestrator receives a task, decides what needs to happen, and routes the task to the right specialized agent. The orchestrator usually does not perform all the work itself.

Why it matters for the next project: the upcoming mini-project uses an orchestrator pattern. The orchestrator will receive raw data and decide which specialized agent should handle it next.
